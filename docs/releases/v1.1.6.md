## 日本語

### 修正：ラップタイムなどの行が一瞬消える・ちらつく

v1.1.5 では、DISPLAY のたびに **全消去 → 全行 → 表示** の 1 フレームを送っていました。HDZero のゴーグルは描画内容を保持し、全消去を受けたときだけ空白になります。そのため、全消去と表示の間で行のパケットが ESP-NOW 上で 1 つでも落ちると、**その行が欠けた画面が表示**され、次の DISPLAY（レースクロックで 1 秒後）まで消えたままになっていました。

**修正**として、全消去を毎回送るのをやめました。

- 各行を幅いっぱい（50 桁、空白込み）で書き込み、前の内容を丸ごと置き換えます
- 空になった行は空白で上書きし、念のため次の 2 回の DISPLAY でも空白を再送します
- 全消去は画面全体を空白にするときだけ送ります（ステージ／ラップ削除／ラップクリア／バインドテスト終了／切断時）
- パケットが落ちても、その行は**直前の表示のまま残り、空白になりません**
- 毎回描き直すタイプのゴーグルにも、DISPLAY ごとに全行が届く点は v1.1.5 と同じです

表示位置・表示時間・メッセージなどの設定は変わりません。

### 推奨：ELRS Netpack の ESP-NOW ブリッジ更新

必須ではありませんが、[elrs-netpack](https://github.com/yanazoo/elrs-netpack) の `main` にある最新の `elrs-espnow-bridge`（Wrover-E / XIAO ESP32-C3）を書き込むと、さらに安定します。

- 電源が入っていない・範囲外のゴーグル宛ての送信が詰まって、他のパイロット宛ての行まで落ちることがなくなります
- 送信キューを 16 → 48 に拡大しました

```bash
pio run -d elrs-espnow-bridge -e esp32dev -t upload       # Wrover-E
pio run -d elrs-espnow-bridge -e xiao_esp32c3 -t upload   # XIAO ESP32-C3
```

（elrs-netpack リポジトリのルートで実行。XIAO 側 `elrs-xiao-webui` の書き換えは不要です）


このバージョンを指定して入れる場合:

- [FPV C5 Lap Timer](https://github.com/yanazoo/FPV-C5-Lap-Timer) の `test/crosscheck_vrxc.py` で検証しました

  - 25 % のパケットロスを模擬したレースで、表示中の行が空白にならないこと（v1.1.5 の方式ではこのテストで行が消えることを確認）

## English

### Fixed: rows (lap time etc.) briefly vanishing and flickering

v1.1.5 sent a full frame on every DISPLAY: **clear, every row, display**. HDZero goggles keep a canvas that only the clear command blanks, so a row write lost on the ESP-NOW hop between clear and display showed the screen **without that row** until the next DISPLAY (the race clock, one second later).

The plugin no longer sends clear on every display:

- every row is written at its full width (50 columns, spaces included), replacing what was there
- a row that became empty is overwritten with spaces, and again on the next two displays
- clear is only sent when the whole screen should go blank (staging, lap delete, laps clear, end of the bind test, disconnect)
- a lost packet now leaves the previous text up instead of blanking the row
- goggles that render each DISPLAY from scratch still get every row on every display, as in v1.1.5

No settings change.

### Recommended: update the ELRS Netpack ESP-NOW bridge

Optional: flash the latest `elrs-espnow-bridge` (Wrover-E / XIAO ESP32-C3) from [elrs-netpack](https://github.com/yanazoo/elrs-netpack) `main`. Bursts to goggles that are off or out of range no longer stall the queue and drop other pilots' rows, and the TX queue grew from 16 to 48. The XIAO (`elrs-xiao-webui`) needs no reflash.
