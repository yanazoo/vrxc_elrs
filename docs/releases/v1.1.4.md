## 日本語

### 修正：ごくまれに1ラップだけラップタイムが表示されない

レース中、あるラップだけラップタイムが表示されず、次のラップでは正常に戻る — という症状が、規則性なくごくまれに発生していました。

**原因**は、ラップタイムが **1ラップにつき1個のパケットでしか送られていなかった**ことです。経路上のどこか1箇所でその1個が失われると、次のラップまで丸ごと1ラップ分ずっと空白のままになります。他の表示（順位・ベストラップ・トータルタイム）は別パケットなので正常に出るため、「ラップタイムだけ抜ける」形になっていました。

経路ごとの保護状況を調べたところ、複数の区間が無防備でした。

| 区間 | 保護 |
|---|---|
| RotorHazard → XIAO | TCP（再送あり）✅ |
| XIAO → Wrover（UART） | なし ⚠️ |
| Wrover → ゴーグルBP（ESP-NOW） | 3回リトライ（数ms以内の連続送信のため干渉に弱い）⚠️ |
| ゴーグルBP → OSD描画 | ESP-NOWのACKはMAC層のみで到達保証にならない ⚠️ |

どの区間が原因かを1つに特定するより、**1個落ちても症状が出ない構造**にする方針としました。

### 変更内容

**ラップ行の冗長送信** — 初回送信の後、同じ行を **0.8秒間隔で2回再描画**します（計3回送信）。

- 再描画は**クリアを伴わない**ため、再描画が失われても画面上の表示が消えることはありません
- 新しいラップが記録されたら、古いラップの再描画は即座に停止します
- 表示時間（ラップ結果表示時間）が再描画間隔より短い設定では再描画をスキップし、従来どおり1回送信になります
- 送信量の増加はUID切替1回＋テキスト数個ぶんで、毎秒送信されるレースクロックに比べれば軽微です

これにより、UART・ESP-NOW・ゴーグル側のいずれで1パケット落ちても表示が抜けなくなります。

### ⚠️ ファームウェアの再書き込みは不要です

本リリースは RotorHazard プラグイン側のみの変更です。**ELRS Netpack（XIAO / Wrover）の書き込み直しは必要ありません。** v2.4 のままお使いいただけます。

### 動作確認

ロジックテスト16項目すべてパス（冗長送信の回数・再描画がクリアを伴わないこと・新しいラップによる停止・表示時間が短い場合の挙動など）。冗長送信を無効化するとテストが失敗することも確認し、検査が有効に機能していることを担保しています。既存テスト13項目にも回帰はありません。

なお本事象は発生頻度が極めて低いため、しばらく実戦で運用して再発しないことの確認を推奨します。

## English

### Fixed: very rarely, a single lap's time would not appear

During a race the lap time would occasionally be missing for exactly one lap and then come back on the next one, at random and very infrequently.

The cause: a lap time was **sent as a single packet, once per lap**. If that one packet was lost anywhere along the path, the row stayed blank for the rest of the lap. Everything else (position, best lap, total time) travels in separate packets and kept displaying normally, which is why only the lap time went missing.

Auditing the path showed several unprotected hops:

| Hop | Protection |
|---|---|
| RotorHazard → XIAO | TCP (retransmits) ✅ |
| XIAO → Wrover (UART) | none ⚠️ |
| Wrover → goggle backpack (ESP-NOW) | 3 retries, all within a few ms so a single interference burst can take all of them ⚠️ |
| Goggle backpack → OSD | the ESP-NOW ACK is MAC-layer only and does not confirm delivery ⚠️ |

Rather than pin the loss on one hop, the fix makes a single loss invisible regardless of where it happens.

### What changed

**The lap rows are redrawn** — after the initial send, the same rows are redrawn **twice at 0.8 s intervals** (three transmissions in total).

- Redraws never clear, so a lost redraw can only delay the text, never erase what is on screen
- A newer lap stops the previous lap's redraws immediately
- If the results uptime is shorter than the redraw interval, redraws are skipped and behaviour is unchanged
- The extra traffic is one UID switch plus a few text packets — minor next to the race clock, which sends every second

### ⚠️ No firmware reflash needed

This release changes only the RotorHazard plugin. **The ELRS Netpack (XIAO / Wrover) does not need reflashing** — stay on v2.4.

### Verified

Because the symptom is so rare, running a few race days before considering it closed is recommended.
