# vrxc_elrs v1.1.9 — 受信の取りこぼし・受信処理の停止・スイッチの繰り返しを修正 / Split frames, a stopped receive loop, repeated switch frames

> **Language / 言語:** [日本語](#日本語) | [English](#english)

<a name="日本語"></a>

## 日本語

### 修正

- **2 回に分かれて届いたデータを取りこぼしていた**
  - ソケット・シリアルとも、1 回の読み込みごとに別々に解析していました。TCP はデータの流れなので、1 つのフレームが 2 回に分かれて届くことがあり、そのフレーム（レースディレクターのスイッチなど）が捨てられていました。
  - 受け取ったデータを、続けて 1 つの解析器で読むようにしました。長さの欄が壊れたフレームが、後ろのフレームを飲み込まないようにもしました。
- **受信処理が止まり、スイッチが効かなくなることがあった**
  - おかしなフレーム（中身が空のスイッチ、文字として読めないバージョン）や RotorHazard 側のエラーで受信ループが終わり、再起動するまでディレクターのスイッチが効きませんでした。
  - エラーは記録して、受信を続けるようにしました。
- **ディレクターのスイッチの繰り返し送信**（FPV C5 Lap Timer と同じ扱い）
  - **トグル**：状態が変わったときだけ動きます。ON のままクリアしても、次のレースが勝手に始まりません。
  - **プッシュ**：前の押下から 1.5 秒以内の ON は、同じ押下の再送として無視します（スタートしてすぐ止まることがありました）。

## English

### Fixed

- **Frames split over two reads were dropped**: each socket / serial read was parsed on its own, so a frame that arrived in two pieces (e.g. the race director's switch) was lost. One parser now runs over the whole stream; a damaged length field no longer swallows the frames after it.
- **The receive loop could stop**: a bad frame (a switch frame with no payload, a version that is not text) or an error from RotorHazard ended it, and the director's switch was dead until a restart. Errors are logged and the loop goes on.
- **Repeated switch frames** (as in the FPV C5 Lap Timer): toggle reacts to a change only, so a switch left on does not start the next race by itself; push takes an "on" within 1.5 s of the last press as the same press (it used to start and at once stop).
